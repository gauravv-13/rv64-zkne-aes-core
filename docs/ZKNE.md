# Zkne (AES encryption) on the 5-stage RV64 core

This core implements the four RV64 instructions of the ratified RISC-V
**Zkne** extension (Scalar Crypto v1.0.1). The results match Spike bit for
bit. The core is meant as a test bench for power side-channel research on
these instructions, so correctness, readable RTL and nets you can probe
come before speed. It is **not** a full RV64I core.

## What was implemented

| Instruction | Operation (Sail, v1.0.1) |
|---|---|
| `aes64es rd, rs1, rs2` | `rd = SubBytes(ShiftRows(rs2:rs1)[63:0])` (final round) |
| `aes64esm rd, rs1, rs2` | `rd = MixColumns(SubBytes(ShiftRows(rs2:rs1)[63:0]))` (middle round) |
| `aes64ks1i rd, rs1, rnum` | `w = SubWord(rnum==0xA ? rs1[63:32] : ror32(rs1[63:32],8)) ^ rcon(rnum)`; `rd = {w, w}` |
| `aes64ks2 rd, rs1, rs2` | `w0 = rs1[63:32] ^ rs2[31:0]`, `w1 = w0 ^ rs2[63:32]`; `rd = {w1, w0}` |

- None of these instructions do AddRoundKey. Software uses `xor`.
- `aes64es` and `aes64esm` read the whole 128-bit state from rs1 (bytes 0..7)
  and rs2 (bytes 8..15) and return one 64-bit half. Software gets the other
  half by swapping the operands:
  `aes64esm t2,t0,t1 ; aes64esm t3,t1,t0`.
- `rcon(0..9) = 01 02 04 08 10 20 40 80 1b 36`. For rnum = 0xA there is no
  rotation and rcon = 0 (used by AES-256).
- rnum 0xB..0xF is reserved and raises `illegal_instr` (see *Known limits*).
- Zknd (decryption: `aes64ds`, `aes64dsm`, `aes64im`) is **not** implemented.
  Those encodings raise `illegal_instr`.

References used:
- The Sail code in the spec, `docs.riscv.org/reference/isa/v20260120/unpriv/scalar-crypto.html`.
- Spike `riscv/insns/aes64{es,esm,ks1i,ks2}.h` and `aes_common.h` (riscv-isa-sim
  commit 609dbe0).

### Encodings

| Instruction | funct7 / imm[11:0] | rs2 | funct3 | opcode | Example word |
|---|---|---|---|---|---|
| `aes64es`   | `0011001` | rs2 | `000` | `0110011` | `aes64es a0,a1,a2` = `0x32c58533` |
| `aes64esm`  | `0011011` | rs2 | `000` | `0110011` | `aes64esm a0,a1,a2` = `0x36c58533` |
| `aes64ks1i` | bits[31:24] = `00110001`, bits[23:20] = rnum | - | `001` | `0010011` | `aes64ks1i a0,a1,0xa` = `0x31a59513` |
| `aes64ks2`  | `0111111` | rs2 | `000` | `0110011` | `aes64ks2 a0,a1,a2` = `0x7ec58533` |

The words above come from GNU as 2.46 with `-march=rv64i_zkne`, which knows
the mnemonics, so no `.insn` is needed. The tests use `.insn` only for
encodings the assembler rejects, such as reserved rnum values and Zknd.

### Register layout and byte order: little-endian only

The core is **little-endian only**, like the RISC-V spec, Spike and GCC.
There is no big-endian mode or switch.

- **Instruction memory:** the byte at the lowest address is instruction bits [7:0].
- **Data memory:** `ld`/`sd` are little-endian.
- **AES state:** follows the spec's register layout. The 16-byte state
  `s[0..15]` is column-major (`s[4c+r]` is row r, column c). `s[0..7]` is in
  rs1 with byte i in bits `[8i+7:8i]`, and `s[8..15]` is in rs2.
- **No byte reversal.** Neither the RTL nor the tests reverse bytes. A
  16-byte block stored in FIPS order (byte 0 at the lowest address) and
  loaded with two `ld` instructions is already in this layout. That's why
  the test data is written as `.byte` lists copied from FIPS-197 and
  SP 800-38A.
- The legacy program image was converted to little-endian once, with
  `scripts/legacy_hex_to_le.py`. No big-endian copy is kept.

## RTL structure

| File | Role |
|---|---|
| `rtl/zkne_unit.v` | The four instructions. Combinational, sits in EX. |
| `rtl/aes_sbox.v` | AES S-box as a `case` statement. Generated by `scripts/gen_aes_sbox.py` from the FIPS-197 definition. |
| `rtl/processor.v` | Pipeline. Instantiates the unit as `ZKNE_UNIT` and picks `ex_result = ID_EX_Zkne ? zkne_result : alu_result`. |
| `rtl/control.v` | Decoder: Zkne decode and `illegal_instr`. |
| `rtl/aes_round64.v` | Old non-standard custom-0 instruction. Only compiled with `-DLEGACY_AES`. |

`zkne_unit` ports: `valid, op[1:0], rs1[63:0], rs2[63:0], rnum[3:0] -> result[63:0]`.
The `op` encoding is `00` es, `01` esm, `10` ks1i, `11` ks2. In EX, funct7
alone tells the four instructions apart.

- **Single cycle in EX, fixed latency, no data-dependent timing (Zkt).**
  There is no FSM and no early exit. The Zkt test checks this: the
  FIPS program takes 90 cycles for every key and plaintext.
- **Forwarding:** rs1 and rs2 come from the same forwarding muxes as the ALU
  (EX/MEM, MEM/WB, and the register file's write-through). A load followed
  immediately by a Zkne instruction that uses it stalls for 1 cycle, the
  same as any other load-use case.
- **Operand isolation:** unless `valid` is high (a legal Zkne instruction
  is in EX), every operand input is forced to 0. rs2 and rnum are also
  zeroed for the instructions that don't use them. Ordinary ALU traffic
  therefore doesn't toggle the AES nets, and a test checks this on the VCD.
  The gating is plain combinational logic. It reduces toggling noise but is
  **not** a masking countermeasure.
- **S-box layer:** one shared layer of 8 `aes_sbox` instances. es and esm
  use all 8; ks1i uses bytes 0..3, and the inputs of bytes 4..7 are 0. To try
  a masked S-box, replace `aes_sbox`, or the generate block `sbox[i]` in
  `zkne_unit.v`.
- **Named nets for probing** (all under `uut.ZKNE_UNIT`):

  | Net | Meaning |
  |---|---|
  | `a`, `b`, `rn` | Isolated operands |
  | `sr` | ShiftRows output |
  | `sb_in`, `sb_out` | S-box layer input and output |
  | `sbox[i].u_sbox.in/out` | Each S-box instance |
  | `mixcol[c].x0..x3`, `t0..t3`, `y0..y3` | MixColumns: inputs, xtime terms, outputs |
  | `mc` | MixColumns result |
  | `ks_w`, `ks_rot` | ks1i word before and after rotation |
  | `rcon`, `ks1_word` | ks1i round constant and result word |
  | `ks2_w0`, `ks2_w1` | ks2 result words |
  | `result` | Unit output |

### Base-ISA changes the Zkne work needed

These changes were made in Step 2.5, one commit and one regression test each.

| Item | Change |
|---|---|
| A | Added `xor`. |
| B | `RESET_PC = 0x80000000`. Memories are 64 KB each, sized by parameters and decoded from the low address bits. Added `lui` and `auipc`. |
| C | Little-endian only. |
| D | `beq`/`bne` decoded properly. **Every** encoding that isn't fully decoded raises `illegal_instr`; there are no silent fallbacks. |
| E | An illegal instruction becomes a NOP, and the testbench fails the run. |
| F | Programs end with a store to `tohost`, the same convention Spike uses. |

The core decodes exactly these instructions:
- `add sub and or xor addi ld sd beq bne lui auipc`
- the four Zkne instructions
- the legacy custom-0 instruction, only with `-DLEGACY_AES`

## How to run

Tools used on macOS (Apple Silicon) with Homebrew:

| Tool | Version | Homebrew |
|---|---|---|
| Icarus Verilog | 13.0 | `brew install icarus-verilog` |
| Verilator | 5.052 | `brew install verilator` |
| riscv64-unknown-elf-gcc / binutils | 16.1.0 / 2.46 | `brew tap riscv-software-src/riscv && brew install riscv-tools` |
| Spike | 1.1.1-dev | installed by `riscv-tools` (formula `riscv-isa-sim`) |
| Python | 3.11 | standard library only |

| Command | What it does |
|---|---|
| `make test` | Runs every test, legacy and new. Prints `[PASS]`/`[FAIL]` per test and a summary. Takes about 15 s. `make test K=<substring>` runs a subset. |
| `make sim` | Runs the legacy program (`tests/legacy`) and prints its register dump. |
| `make sim PROG=<file.S\|file.elf>` | Runs a program and writes a full VCD to `build/vcd/`. |
| `make vcd PROG=<file.S\|file.elf>` | Writes `build/vcd/<name>_zkne.vcd` with **only** the Zkne unit's signals, for toggle-count analysis. |
| `make lint` | `verilator --lint-only -Wall` on the core. Clean. Intentional cases are waived, with reasons, in `scripts/lint_waivers.vlt`. |
| `make clean` | Removes `build/`. |

Environment variables for the random tests:
- `ZKNE_SEED` (default `20261003`)
- `ZKNE_N`: random vectors per instruction (default 10000)
- `ZKNE_PROG_N`: length of the random program (default 3000)

Writing a test program:
- `#include "test.h"`, start at `_start` in `.text.init`, and end with
  `TEST_END` (pass) or `TEST_FAIL(code)`.
- These macros clobber x29 and x30, and use local label 99.
- `// EXPECT: xN = 0x...` and `// EXPECT_MEM: 0xADDR = bytes...` lines are
  checked by the runner. `sw/link.ld` puts code at `0x80000000`, data at
  `0x80008000` and `tohost` at `0x8000f000`.

### What `make test` runs (28 tests)

- **Legacy:** the original program, built with `-DLEGACY_AES` and
  `RESET_PC=0`, still gives the original 32 registers and 21 cycles.
- **Base ISA (A–F):**
  - xor, lui/auipc/la, little-endian byte order (stores checked byte by
    byte), beq/bne.
  - 48 undecoded encodings, each reported exactly once.
  - Illegal instruction is a NOP; by default the run fails at the first one.
  - tohost exit with pass and fail codes.
- **Zkne directed:**
  - FIPS-197 C.1 intermediate values: round keys 1–2, ks1i with rnum=0xA,
    round 1 MixColumns output, round 10 ShiftRows output.
  - rnum 0xB..0xF raise `illegal_instr`.
- **Golden model** (`scripts/zkne_golden.py`): written from FIPS-197 and the
  Sail code, not from the RTL. Its self-test runs FIPS-197 C.1 both through a
  textbook AES-128 and through AES-128 built from the four instructions.
- **Random, RTL vs golden:** edge cases plus 10,000 random operand sets per
  instruction on `zkne_unit` (about 48,000 vectors), plus `valid=0 → 0`.
- **FIPS-197 C.1 in assembly** (`tests/zkne/fips197_c1.S`): key expansion with
  `aes64ks1i`/`aes64ks2`, ciphertext `69c4e0d86a7b0430d8cdb78070b4c55a`.
- **Zkt:** the FIPS program with 4 different key/plaintext sets takes the
  same number of cycles.
- **Pipeline:**
  - Forwarding on both operands, including the back-to-back swapped
    `aes64esm` pair.
  - Load-use into esm/es/ks1i/ks2.
  - Taken branches squashing Zkne instructions, including a squashed
    reserved-rnum ks1i that must not report as illegal.
- **Random program:** 3000 random Zkne/xor/ld instructions with operands biased
  toward recent results (hazards). Checked core vs golden simulation and core
  vs Spike.
- **Lockstep with Spike:** every program Spike can run (see below).
- **Demo:** AES-128 CTR against NIST SP 800-38A F.5.1, plus the
  Zkne-unit-only VCD and operand isolation.

## Comparison with Spike

Each program in the lockstep set is assembled once. The same ELF then runs:
- on the core, where the testbench logs every register write at WB (rd ≠ 0)
  and every store at MEM;
- on `spike --isa=rv64i_zkne -m0x80000000:0x10000 -l --log-commits`.

The runner compares the **order and value of every register write** and
every store, skipping the boot ROM (PC < 0x80000000) and writes to x0.

## AES-128 CTR demo (`sw/aes128_ctr.S`)

- Key expansion runs once, and the 11 round keys stay in x6..x27.
- Four CTR blocks follow, with the counter blocks precomputed in data
  memory. All four ciphertext blocks match NIST SP 800-38A F.5.1.

| | Cycles |
|---|---:|
| **Per block (steady state)** | **54**: 52 instructions (2 `ld` + 2 `xor` for the counter, 9×4 middle-round, 4 final-round, 2 `ld` + 2 `xor` for the plaintext, 2 `sd`, `addi`, `bne`) + 2 for the taken `bne` |
| First block done (includes key expansion) | 90 |
| Total for 4 blocks (as counted by the testbench) | 259 |

Branches are predicted not-taken and resolved in EX. Unrolling the loop
would save the 2-cycle penalty; it was left as a loop for clarity.

## Known limits

- **No traps.** The core has no CSRs and no exception mechanism. An illegal
  instruction becomes a **NOP**: no register write, no memory access, no
  branch. The testbench prints
  `ERROR: illegal instruction ... at pc ...` and the run fails
  (`RESULT: ILLEGAL`). `+ALLOW_ILLEGAL` reports illegal instructions without
  stopping; only the tests of the decoder use it.
- **aes64ks1i with rnum > 0xA differs from Spike.** The spec says reserved,
  and Sail calls `handle_illegal()`. Spike raises an illegal-instruction trap.
  This core turns it into a NOP plus a test failure, as above.
- **Subset of RV64I.** Only `add sub and or xor addi ld sd beq bne lui auipc`.
  There's no `jal`/`jalr`, no shifts, no byte/word loads or stores, and no
  CSRs; all of these raise `illegal_instr`. GCC pseudo-instructions that
  expand to unsupported instructions (for example `li` with a large
  constant, which uses `slli`) can't be used. Load constants with `la` + `ld`.
- **Memories.**
  - Separate instruction and data memories, 64 KB each, decoded from the
    low address bits. Addresses alias every 64 KB.
  - Both memories are loaded from the same ELF image, but stores reach only
    data memory, so there's no self-modifying code.
  - Data memory isn't cleared by reset.
- **Misaligned `ld`/`sd`** run byte by byte, wrapping inside the memory.
  Spike traps on misaligned accesses unless Zicclsm is enabled, which is why
  `endian.S` runs on Spike with `--isa=rv64i_zkne_zicclsm`.
- **Extra stalls.** The hazard unit compares the rs2 *field* even for I-type
  instructions. That includes `aes64ks1i`, whose bits[24:20] are
  `{1, rnum}`, so a load just before can cause an extra stall. This depends
  on the instruction encoding and register numbers, never on data, so Zkt
  still holds.
- **Legacy instruction.** `aes_round64` (custom-0) isn't AES: it treats 64
  bits as the whole state. It's kept, unchanged, only behind
  `-DLEGACY_AES` for the legacy regression test. Without that define its
  encoding is illegal.
- **Operand isolation isn't masking.** Combinational gating can still glitch.
  The unit is unprotected AES.
